# Interface egui (`planrs-ui-egui`) — fondations

État au 2026-10-18 (branche `ui-foundations`, tête 1d3eb09, ADR-0011, après la passe de corrections de la relecture). L'interface est **en lecture seule** : elle ouvre un fichier MSPDI, laisse le moteur calculer le planning et l'affiche (table des tâches et Gantt synchronisés, zoom, thème clair/sombre, français/anglais), sur le desktop et sur le web avec le même code. Aucune édition tant que le registre de commandes (J4) n'existe pas. **Mise à jour J4, lot L11 (2026-10-19)** : le document est une session d'édition de `planrs_automation` ; annuler, rétablir et les raccourcis sont câblés (§ 1.12). La saisie dans les cellules vient avec L12. Ce document décrit le code tel qu'il est ; les noms de types et de fonctions viennent tous de `crates/planrs-ui-egui/src/`.

## 1. Architecture

### 1.1 Crates et couches

| Crate | Rôle |
|---|---|
| `crates/planrs-ui-egui` | Toute l'interface : état, vues, ouverture, i18n, thème. Dépend de `planrs-core`, `planrs-mspdi`, egui, eframe, rfd, fluent-bundle, unic-langid, sys-locale (en wasm32 : wasm-bindgen-futures, js-sys, rfd avec la feature `file-handle-inner`). Seule crate de bibliothèque autorisée à dépendre d'egui/eframe/rfd (règle 9, `cargo xtask layers`). |
| `apps/planrs` (binaire `planrs-desktop`) | Fenêtre eframe native (1440×900, minimum 800×500) ; lit l'horloge locale (`chrono::Local`) et la langue du système, puis les injecte (`Env`). Feature `persistence` d'eframe. |
| `apps/planrs-web` (binaire `planrs-web`) | Même interface en `wasm32-unknown-unknown`, servie par trunk ; « maintenant » par `js_sys::Date`, langue par `navigator.language` (feature `js` de sys-locale). Compilée pour une cible native, le binaire indique seulement qu'il faut passer par trunk. |

Point d'entrée unique : `planrs_ui_egui::ui(ui: &mut egui::Ui, app: &mut App)`, appelé tel quel par le desktop et le web (via `PlanrsApp`), par les tests kittest (`Harness::build_ui_state`), par le test de fluidité et par l'exemple `snapshot`. `App` ne dépend pas d'eframe ; `PlanrsApp` (`shell.rs`) est le seul type qui implémente `eframe::App`.

### 1.3 Flux d'une image

```text
eframe (desktop/web)            kittest / perf / snapshot
  PlanrsApp::raw_input_hook       (sanitize_raw_input : événements non finis retirés)
  PlanrsApp::ui(ui, frame)        Harness::build_ui_state ou Context::run_ui
            \                          /
             planrs_ui_egui::ui(ui, &mut App)
                         |
                   App::show(ui)
   1. poll_io()        relève les OpenEvent du canal mpsc (ouverture finie)
   2. apply_theme()    ctx.set_theme seulement si ThemePref a changé
   3. apply_language() Texts, RowModel et DiagnosticsView reconstruits si la
                       langue résolue change
   4. Palette::for_theme(ctx.theme())   (thème résolu, jamais la préférence)
   5. FrameCtx { state, doc, rows, texts, palette, metrics, diagnostics,
                 selection, actions: &mut Vec<Action>, stats: &mut FrameStats }
         |-- view::chrome::menu_bar      (Panel::top)
         |-- view::chrome::toolbar       (Panel::top, horizontal_wrapped)
         |-- view::chrome::status_bar    (Panel::bottom + bandeau de messages)
         |-- view::diagnostics::panel    (si UiState.diagnostics_open)
         `-- CentralPanel
               |-- document ouvert : view::main_view::show(ui, fc, &mut ViewTransient)
               |      geom::main_layout -> MainLayout (Gantt arrêté à Metrics::vbar_w du bord)
               |      relevé last_gantt_width / last_gantt_left dans ViewTransient
               |      TimeAxis::new(range, zoom, gantt_clip.left() - gantt_scroll_x)
               |      table::paint_header, timescale::paint_header
               |      ScrollArea::vertical().show_viewport  (ScrollStyle::solid)
               |          geom::visible_rows(viewport, ROW_H, len, OVERSCAN)
               |          table::paint_body  + gantt::paint_body   (même plage)
               |      molette X, Ctrl+molette, séparateur, barre horizontale
               `-- sinon : view::chrome::welcome
   6. last_frame = FrameStats (lignes table/Gantt, liens, formes)
   7. réducteur : App::apply(action) pour chaque Action de l'image
   8. fit_if_needed() (zoom ajusté après une ouverture), request_repaint si
      une action ou un ajustement a eu lieu
```

Les vues ne modifient jamais `App` : elles lisent `FrameCtx` et poussent des `Action`. L'effet d'une action est donc visible à l'image suivante (une image de plus est demandée). `App::dispatch` met une action en file depuis l'extérieur (tests, exemple).

`sanitize_raw_input` retire les événements de pointeur, de molette, de zoom, de rotation et de toucher qui portent une composante non finie (NaN, infini) : egui échouerait sur une assertion avant tout code planrs.

### 1.4 Ouverture d'un fichier

- **Exemple embarqué** : `Action::OpenDemo` → `App::open_demo` → `App::open_bytes(DEMO_MSPDI, origin)`, synchrone.
- **Desktop** : `Action::OpenDialog` → `RfdFileService::pick_and_open` : un fil `planrs-open` est d'abord créé (échec → erreur d'ouverture affichée, aucune boîte ouverte), puis `rfd::AsyncFileDialog` est créé **sur le fil d'interface** (filtre `.xml`, titre traduit « Ouvrir un fichier MSPDI ») et son futur est envoyé au fil, qui l'attend par `pollster::block_on`, lit le fichier par `std::fs::read` (jamais `FileHandle::read`) et appelle `document::load`. Sur macOS, rfd attache le sélecteur à la fenêtre principale comme **feuille** (`beginSheetModalForWindow:completionHandler:`), qui rend la main aussitôt : l'interface continue de se dessiner et aucune boucle modale ne tourne dans le gestionnaire d'événement de winit. Jamais de `rfd::FileDialog` synchrone : sa boucle modale imbriquée fait avorter winit 0.30 sur macOS (ADR-0011, relecture sur Mac). Le résultat (`OpenEvent::Opened` ou `Cancelled`) part dans un `std::sync::mpsc`, `request_repaint` réveille l'interface, et il est relevé au début de l'image suivante.
- **Web** : même action → `rfd::AsyncFileDialog` (téléversement par un `<input type=file>` généré par rfd) lancé par `wasm_bindgen_futures::spawn_local` ; lecture par `Blob::arrayBuffer` (`read_web_file`, sur le `web_sys::File` rendu par `FileHandle::inner`, feature `file-handle-inner` de rfd) : une promesse rejetée devient `OpenError::Read` avec le message JavaScript, un contenu vide est refusé par le lecteur MSPDI. Tout chemin qui se termine envoie un `OpenEvent`. Aucun fichier ne quitte le navigateur (note de l'accueil).
- **Relance de « Ouvrir »** : `App::is_opening` n'est qu'un indicateur. Une nouvelle demande pendant une ouverture en cours abandonne la précédente (nouveau canal ; son résultat éventuel, envoyé dans l'ancien canal fermé, est ignoré) et relance le sélecteur : un sélecteur web qui ne répond jamais (pas d'événement `cancel`) ne bloque pas « Ouvrir ». Sur macOS, la feuille bloque les clics sur la fenêtre : pas de second « Ouvrir » possible. Sur Windows et Linux, le sélecteur n'est pas rattaché à la fenêtre (pas de `set_parent`, `App` ignore eframe) : un second « Ouvrir » ouvre un second sélecteur et le résultat du premier est ignoré (non testé sur ces plateformes).
- Un échec devient un `UserMessage` d'erreur traduit (bandeau refermable, jamais de modale) ; le document précédent reste affiché. Une ouverture réussie retire les erreurs d'ouverture précédentes et l'avertissement de troncature.
- `document::load` ouvre une `Session` (`Session::open_bytes`) qui calcule le planning (règle 3 : aucune date calculée par l'interface) ; il est recalculé par le moteur à chaque lot de commandes (§ 1.12). `App::install` attribue un numéro d'ouverture (`OpenDocument::opening`, la génération de la session repartant de 0), reconstruit le `RowModel` et la `DiagnosticsView`, efface la sélection, remet la vue à zéro et demande l'ajustement du zoom ; si `LoadedDocument::range_truncated`, il ajoute l'avertissement traduit `range-truncated` (« Plage d'affichage limitée à 20 ans »).

### 1.5 Environnement injecté (`Env`)

`Env { now: Box<dyn Fn() -> Moment>, system_language: Option<Language>, files: Box<dyn FileService> }` est la seule porte vers l'horloge, la langue du système et les fichiers. `now` sert de `ReadOptions::current_date` à chaque ouverture. `Env::fixed(now)` (tests, perf, exemple) : date fixe, aucune langue système (repli français), `NoFileService` qui répond `Cancelled`. Le `clippy.toml` de la crate interdit `chrono::Utc::now`, `chrono::Local::now`, `SystemTime`, `Instant` et `std::thread::spawn` (déterminisme, et ces appels paniquent en wasm32).

### 1.6 État persistant (`UiState`) et compatibilité

`UiState` (serde, `#[serde(default)]`, `UiState: Eq`, **aucun `f32`**) : `version`, `language`, `theme`, `zoom` (écrasé par l'ajustement à chaque ouverture), `columns` (une entrée par colonne dans l'ordre de `Column::ALL` : visibilité, largeur en points entiers), `table_width` (points entiers), `diagnostics_open`.

- JSON compact déterministe (`to_json`), JSON de référence `tests/fixtures/ui_state_v1.json` vérifié par `ui_state_default_json_reference`.
- Lecture tolérante `UiState::from_json_lenient`, **champ par champ** : champ absent → défaut ; champ inconnu → ignoré ; champ illisible → sa valeur par défaut, les autres conservés, `StateLoadError::Fields` (noms des champs) ; colonne illisible → ignorée ; JSON illisible → état par défaut + `StateLoadError::Json` ; autre chose qu'un objet → `StateLoadError::NotObject` ; `version` > `UI_STATE_VERSION` (1) → état par défaut + `StateLoadError::TooNew` (lu avant le reste). L'avertissement est affiché une fois (`App::report_state_load`), jamais bloquant.
- `normalized()` borne les largeurs, complète et dédoublonne les colonnes, force ID et Nom visibles.
- J8 (ADR-0016, contrat L0) : `task_view` (`TaskViewPrefs` : niveau affiché 1 à 9 ou tous, surbrillance du critique), `default_template` (Classique jusqu'à L15, Sobre depuis), `user_templates` (`NamedStyle`, 32 au plus, nom ≤ 64 caractères, entrée illisible écartée seule), `write_style_to_file` (vrai) ; version 1 gardée, état J7 lu sans avertissement (`tests/fixtures/ui_state_v1_j7.json`, `ui_state_v1_j7_reads_without_new_fields`, `ui_state_v1_roundtrip`). Filtre, tri, repli et recherche (`TaskViewState`, `SearchState`) ne sont pas persistés.
- ADR-0017 (contrat L0 du ruban) : `ribbon` (`RibbonPrefs` : onglet `task`, `resource`, `project`, `view` ou `format`, Tâche par défaut ; `collapsed`, faux) et `timeline_visible` (vrai, H-UI-78) ; version 1 gardée, état J8 lu sans avertissement (`tests/fixtures/ui_state_v1_j8.json`, `ui_state_v1_fixture`) ; référence `ui_state_v1.json` régénérée une fois. L'habillage (`ribbon::Chrome`) n'est pas persisté.
- Règle de version : ajouter un champ avec défaut ne change pas la version ; retirer, renommer ou changer le sens d'un champ l'incrémente.
- Hors de l'état persistant : document ouvert, sélection, `ViewTransient` (défilements, ajustement en attente, accumulateur de zoom, largeur et bord du Gantt de l'image précédente), messages, caches.

### 1.7 Modèle de lignes (`RowModel`) et diagnostics (`DiagnosticsView`)

`RowModel::build(doc, labels)` est appelé à l'ouverture et au changement de langue, jamais pendant une image :
- une `Row` par tâche, **dans l'ordre des ID** (aucun tri) : UID, ID, niveau, `RowKind` (`Null`, `Leaf`, `Summary`, `Milestone`, `Excluded`), criticité, barre `(début, fin)` prise dans `TaskSchedule.start/finish` (ou la barre d'affichage d'une tâche exclue) ;
- les textes des 8 colonnes, pré-formatés ligne par ligne (`RowModel::text(i, column)`) ;
- les liens (`LinkView { from, to, kind, critical }`, critique si ses deux extrémités le sont) triés par `min(from, to)` ; `links_touching(range)` rend les liens dont l'intervalle de lignes coupe la plage visible (un lien long qui traverse la fenêtre est gardé), par dichotomie puis balayage borné ;
- `index_of(uid)` en O(log n) (`BTreeMap`).

J8 (lot L5) : l'ordre affiché (filtre, tri, repli) ne touche pas le `RowModel` ; il passe par `RowView` (§ 1.23).

`DiagnosticsView::build(doc)` (même moments, cache d'`App`, `App::diagnostics_view`) : diagnostics d'import puis de calcul, mis en texte (`Display` du cœur, en français), triés par gravité de façon stable, avec les compteurs `errors` et `warnings` ; « → » (U+2192, absent des polices d'egui) y est remplacé par « -> ». Aucune image ne refait ce travail proportionnel au nombre de diagnostics.

### 1.8 Échelle de temps (`TimeAxis`) : aucun pixel → date

- Zoom discret `TimeScaleZoom::{Day, Week, Month, Quarter}` : 36 ; 12 ; 3,5 ; 1,2 px par jour ; paires d'en-têtes semaine/jour, mois/semaine, trimestre/mois, année/trimestre. Étiquettes choisies par largeur estimée, de la plus longue à la plus courte ; semaine : « 2 nov. » / « Nov 2 », puis numéro ISO préfixé (`tier-week` : « S45 » / « W45 »), puis le jour seul.
- `default_range` (rend `DefaultRange { span: ViewSpan, truncated }`) : début du projet − 7 jours, fin + 21 jours ; étendue à la date d'état effective **seulement** si celle-ci est à `STATUS_REACH_DAYS` (90) jours ou moins de cette plage et que l'extension reste sous `MAX_RANGE_DAYS` (7 305 jours, 20 ans) ; sinon la date d'état est hors champ (sa ligne n'est pas dessinée), ce qui couvre une horloge en panne repliée sur `Moment::MIN`. Début reculé au premier jour de semaine du projet ; un projet de plus de 20 ans est tronqué et `truncated` vaut vrai (message traduit).
- `fit_zoom(range, largeur)` : `Week` si toute la plage tient dans la largeur du Gantt ; sinon `Month`, sauf si la plage au zoom Mois dépasse `QUARTER_FIT_FACTOR` (1,5) fois la largeur, auquel cas `Quarter` ; largeur nulle ou non finie → `Month`. Appliqué à chaque ouverture dès que la largeur est connue (défilement seulement borné), et par le bouton « Ajuster » (`Action::FitZoom`, ancré au centre).
- `TimeAxis::x(Moment) -> f32` est le **seul** sens de conversion : écart entier en minutes (`i64`) à l'origine, puis une seule conversion en `f32`. Depuis J8 (lot L11), `TimeAxis` porte aussi l'axe entier du rendu (`axis16()`, `planrs_render::geometry::Axis16::for_days`, même plage, même échelle exacte : Trimestre 96/5 seizièmes par jour) : la géométrie partagée travaille dessus, l'écran projette les instants en `f32` (§ 1.26). Il n'existe aucune méthode inverse publique. Les gestes ne produisent que des indices de ligne (`geom::row_at`) ou des deltas en pixels (`ScrollGanttX`, `ZoomStep { anchor_x }`, `zoom_anchor`). Seule exception, privée et réservée au dessin : `TimeAxis::first_day_at_or_before` cherche par dichotomie le premier jour visible pour borner l'en-tête et la grille.
- **Ancrage du zoom.** `App::zoom_to(zoom, ancre)` garde à la même place le point du contenu situé à `ancre` pixels du bord gauche du Gantt (ancre bornée à la largeur du Gantt, non finie → 0), par `zoom_anchor`, puis borne le défilement. Ctrl/Cmd+molette (ou pincement, `zoom_delta`) au-dessus du Gantt : un pas par facteur 1,25 cumulé, `ZoomStep.anchor_x` = abscisse du pointeur **relative au bord gauche du Gantt** (le point sous le pointeur ne bouge pas). Boutons et menu de zoom (`SetZoom`) et « Ajuster » : ancrés au centre du Gantt visible (`last_gantt_width / 2`), sans saut dans le temps.
- Molette horizontale (ou Maj+molette) et glisser sur le Gantt : défilement horizontal, borné à `[0, largeur du contenu − largeur visible]`.
- **Amendement J7 (ADR-0015 D5).** Les gestes sur les barres (lot L8) produisent en plus un **écart en jours entiers** : `TimeAxis::days_for_dx(dx: f32) -> i64` (arrondi au plus proche, non fini ⇒ 0, borné à ±`MAX_RANGE_DAYS`). C'est un écart, jamais un `Moment` : `planrs_automation::gesture` le traduit en lot de commandes et le moteur calcule les dates (règle 3). L'interface ne produit donc que des indices de ligne, des deltas en pixels et des écarts en jours entiers.
- **Gestes sur les barres (J7, lot L8, H-UI-20, H-UI-21, R-240 à R-243).** Au début d'un glisser du fond du Gantt, `view::gantt::hit_test` donne la cible du point d'appui (`geom::GanttHit` : intérieur, bord gauche, bord droit d'une barre — zones pures de `geom::bar_zone` —, tracé d'un lien à 3 points près, ou rien) ; une zone de barre devient `ViewTransient::drag: Option<BarDrag>` (tâche, geste, abscisse d'appui relative au Gantt, écart en jours, ligne survolée, aperçu), sinon le glisser fait défiler comme avant. À chaque image, l'écart vient de `days_for_dx` (depuis le point d'appui ; depuis le début de la barre pour l'avancement) ; `gesture::preview` n'est rappelé que si l'écart change et le planning n'est jamais recalculé. Fantôme : contour de la barre aux dates de l'aperçu (`TimeAxis::x`, sens date → pixel), bande au % de l'aperçu, ou trait vers la ligne survolée pour un lien. Lâcher : `Action::ExecOn` d'un seul lot (`bar_move`, `bar_resize`, `progress_drag`, ou `link_drag` si le pointeur est sur la barre d'une autre tâche, `gantt::hit_test` au point de lâcher), une entrée d'annulation ; refus du geste ⇒ `Action::GestureRefused` (bandeau, « Geste impossible sur cette barre : tâche commencée ») ; refus du registre ⇒ bandeau comme toute saisie. Échap annule le glisser. Curseurs : redimensionnement sur les bords, main sur l'intérieur et sur un lien. Double-clic (ou triple) : sur une barre, « Informations sur la tâche » (H-UI-19) ; sur un lien, boîte « Dépendance » (`dialog::link` : de, à, type, décalage au format de R-141, OK ⇒ `link.update` des seuls champs changés, Supprimer ⇒ `link.remove`, refus affichés dans la boîte, brouillon relu si le document a changé). Tests : `tests/ui/gestures.rs` (`h_ui_20_zones`, `h_ui_20_drag_empty_scrolls`, `h_ui_21_link_dialog_updates_lag`, `gesture_single_undo_entry`, `gesture_preview_no_recalc`, …), `geom.rs` (`h_ui_20_bar_zones`), `timescale.rs` (`days_for_dx_*`), perf `bar_drag`.

### 1.9 Palette et thème

J8 (ADR-0016 D5, D6) : `Palette::from_style(&PlanStyle, Variant)` dérive la palette d'un style du planning (`planrs_render::style`) ; le modèle Classique la reproduit champ par champ (`classique_equals_j7_palette`) ; les contrastes de test passent par `planrs_render::style::contrast_ratio` (entiers, millièmes). Depuis L11, l'écran lit la palette du style effectif du document (§ 1.26) ; `Palette::LIGHT` / `DARK` restent celles de Classique.

`ThemePref::{System, Light, Dark}` ; `ctx.set_theme` n'est appelé qu'au changement. La palette (`Palette::LIGHT` / `Palette::DARK`, une seule pour la table et le Gantt) est choisie sur le thème **résolu** (`ctx.theme()`). Couleurs propres (hypothèses H-UI) : barres bleues, barres critiques rouges, récapitulatives et jalons sombres (clairs en thème sombre), récapitulative critique en rouge sombre (`summary_critical`), date d'état en tirets violets. `non_working` grise les jours chômés du calendrier du projet (J7 lot L7, § 2) ; `baseline` (gris) et `progress` (presque noir, sombre en thème sombre) servent au Gantt de suivi (H-UI-22). Tests de contraste et de distinction dans `theme.rs`, dont le bandeau (`palette_message_banner_contrast` : `text_strong` sur `message_error_bg` / `message_warning_bg` ≥ 4,5:1 dans les deux thèmes).

### 1.10 Langues et garde « aucune chaîne en dur »

- `locales/fr.ftl` et `locales/en.ftl`, embarqués par `include_str!` ; identifiants `TextId` générés par `text_ids!` (une clé libre ne compile pas). `Texts::get` / `get_args` ; repli anglais → français → clé brute (journalisée une fois), jamais de panique ; `set_use_isolating(false)`. `Texts::format_labels()` rend des `FormatLabels` construits une fois par langue (plus de recherche fluent par image).
- Règle de pluriel par langue, lue dans la clé `fmt-plural-rule` (FR `below-two` : singulier si |v| < 2 ; EN `exactly-one` : singulier si |v| = 1 ; repli `exactly-one`) → `FormatLabels::plural: PluralRule`.
- `LanguagePref::{System, Fr, En}` résolue par `Language::resolve` (système absent → français).
- Gardes automatiques (`i18n.rs`) : clés FR = clés EN = `TextId::ALL`, mêmes variables, aucune marque d'isolation U+2068/U+2069, aucune espace fine insécable U+202F (absente des polices par défaut), typographie française, tous les messages formatables.
- « Aucune chaîne en dur » : règle de relecture, **pas un test automatique**. Indices indirects : les tests kittest cherchent les widgets par des libellés construits par `Texts`, et le contrôle d'accessibilité de kittest échoue sur un widget sans nom ; mais rien ne détecte un littéral visible écrit dans une vue.
- Noms de mois et de jours dans les `.ftl` (pas de `chrono/unstable-locales`). Les diagnostics montrés à l'ouverture et les erreurs de lecture MSPDI sont traduits par leur code depuis J8 lot L14 (§ 1.29, `docs/ui-needs.md` N5, N9 clos).

### 1.12 Édition : session, annuler/rétablir, raccourcis (J4, lot L11)

- **Document.** `OpenDocument { session, import_diagnostics, range, origin, opening }` : `project()`, `schedule()` et `generation()` lisent la session ; `cache_key() = (opening, generation)` ; `set_origin` change l'origine ici et dans la session (nom, chemin ; le drapeau `demo` reste côté interface). La session ne doit pas être modifiée directement : tout passe par `App`.
- **Édition.** `Action::Exec(Batch)` → `App::execute(&Batch, EditOrigin::User)` → `Session::apply(Commit)` ; `Action::Undo`/`Redo` → `App::undo`/`redo`. Après un commit, une annulation ou un rétablissement, `App::refresh` reconstruit `RowModel` et `DiagnosticsView`, prend pour plage l'union de l'ancienne et de la nouvelle plage par défaut (la nouvelle seule au-delà de 20 ans), garde la sélection par UID et les défilements (bornés). Tâche active disparue (suppression, annulation d'une insertion, écriture d'un agent) : la tâche qui occupe maintenant sa ligne devient active, ou la dernière en fin de liste, comme MS Project ; la ligne vide seulement s'il ne reste aucune tâche (relecture finale J7, F4 : le curseur sautait sur la ligne vide de fin, souvent hors de l'écran). Un lot vide ne rafraîchit rien.
- **Refus.** Un `CommandError` venant de l'utilisateur s'affiche dans le bandeau sous le titre « Modification refusée » (`command-error-title`) ; texte = clé `error-<code>` (points changés en tirets, `task.not_found` → `error-task-not_found`, `i18n::error_text_id`), argument `$detail` = `CommandError::message` dans la langue de l'interface. Une clé par code stable du moteur (`error::codes` et `text.*`), vérifiée par `ui_ftl_keys_for_all_error_codes` qui relève les codes dans les sources du moteur. `EditOrigin::Agent` (canal, J7) : refus rendu à l'appelant, rien n'est affiché. « Rien à annuler » : aucun message. Une édition réussie retire les refus affichés. Chaque message du bandeau porte son titre (`UserMessage::title`), affiché une fois par suite de messages de même titre.
- **Raccourcis.** `keymap::KEYMAP: &[(KeyContext, Shortcut, Binding)]`, `Binding::Command(id du registre)` ou `Binding::Ui(UiBinding)` : Ctrl/Cmd+Maj+Z et Ctrl/Cmd+Y → `history.redo`, Ctrl/Cmd+Z → `history.undo` (contexte `Document`), Ctrl/Cmd+O → ouvrir (contexte `Global`). Lus avant le dessin (touche consommée), jamais pendant la saisie dans un champ de texte (`Context::text_edit_focused`). egui ignorant Maj et Alt en trop, la combinaison la plus précise d'une touche vient d'abord (test). Chaque id existe dans `REGISTRY` et est listé (`ui_keymap_commands_exist_in_registry`) ; un test par entrée vérifie son effet. Une touche répétée dans une même image donne une action par appui (au plus 8).
- **Navigation au clavier (J7, lot L1, ADR-0015 D1-D3).** Contexte `KeyContext::Table`, actif ssi la table a le focus clavier d'egui (`view::table::table_id()`, widget focalisable sans clic qui couvre la table) **et** le volet `Pane::Table`, sans saisie ouverte, menu surgissant ouvert à l'image précédente (`any_popup_open`, relevé en fin d'image : les raccourcis sont lus avant le dessin), fenêtre ni confirmation de suppression (`keymap::KeyState`). Le verrou de focus d'egui (`Memory::set_focus_lock_filter`, Tab et flèches retenus, Échap non) est rappelé à chaque image tant que la table a le focus : sans lui, egui déplacerait le focus en début d'image (test de mutation : 9 tests de `tests/ui/nav.rs` échouent sans). Focus : ouverture d'un document (curseur et sélection sur la première ligne, colonne Nom), clic sur une ligne ou sous la table, fin de saisie au clavier (Entrée, Tab, Échap), clic relâché hors de la table et du Gantt sans autre widget focalisé (barre d'outils, menus, bandeau, réponse d'une confirmation : egui retire le focus à tout appui ailleurs, la table le reprend à l'image suivante ; relecture finale J7, F5, test `nav_focus_back_after_toolbar_click`) ; un clic dans le Gantt le retire (`Pane::Gantt`), Échap aussi (jusqu'au prochain clic hors du Gantt). (Remplacé par H-UI-101, ADR-0018 D8, à partir du lot L1 : un clic dans le Gantt laisse le clavier à la table.) Entrées : ↑/↓, Entrée/Maj+Entrée (ligne), ←/→, Tab/Maj+Tab (colonne visible, colonnes calculées comprises, sans retour à la ligne), Origine/Fin et Ctrl+←/→ (premier, dernier champ), Ctrl+↑/↓ (première, dernière ligne, ligne vide comprise), Ctrl+Origine/Fin, Page haut/bas (`nav::page_rows` − 1 lignes, au moins une), Maj+↑/↓, Maj+Page, Ctrl+Maj+↑/↓ (extension de la **plage de lignes** depuis l'ancre `Selection::anchor`, jamais jusqu'à la ligne vide). Passe UX (ADR-0018, contrat L0) : Maj+←/→, Maj+Origine/Fin, Ctrl+Maj+Origine/Fin et Ctrl+Maj+←/→ sont lus comme extensions (`Nav { extend: true }` ; en L0 la plage reste de lignes, en colonnes à partir de L1, H-UI-92) ; Ctrl/Cmd+A, Ctrl+Maj+Espace, Maj+Espace, Ctrl+Espace, Maj+Retour arrière, Ctrl/Cmd+D, Ctrl/Cmd+Suppr : contexte `Table` (§ 1.34). Contexte `Document` : Alt+←/→ (un jour de l'échelle, `px_per_day` du zoom), Alt+Page (une largeur du Gantt), Alt+Origine/Fin (début du projet au bord gauche, fin au bord droit), Ctrl+/ et Ctrl+= ou Ctrl++ (zoom plus fin), Ctrl+- (plus grossier), ancrés au centre et pris avant le zoom de l'interface d'egui (traité en fin d'image), Alt+Maj+↑/↓ (`task.move`, H-UI-29 : la sœur précédente passe après le bloc sélectionné, la suivante avant ; rien au bord ou pour une sélection non contiguë ; une entrée d'historique). Ctrl = Cmd sur Mac (`Modifiers::COMMAND`, un Mac envoie `mac_cmd` et `command`). Réducteur : `Action::Nav` → `nav::step` sur (indice de ligne, indice de colonne visible) puis UID ou ligne vide ; la sélection suit la ligne du curseur ; `nav::ensure_visible` (marge d'une ligne sauf aux bords) pose `pending_scroll_y` à partir du défilement et de la hauteur relevés à l'image précédente (`ViewTransient::last_scroll_y`, `last_body_height`) ; un défilement imposé est borné par le maximum de l'image précédente (connu d'egui) et le reste attend l'image suivante, sans quoi egui le ramène par un rebond animé (ligne ajoutée en fin de saisie de la ligne vide). Défilement horizontal de la table : lot L6.
- **Menu Édition.** Annuler, Rétablir (grisés sans lot à annuler ou à rétablir), puis les six commandes de structure du menu contextuel (§ 1.15 ; grisées sans document, et sans sélection sauf « Insérer une tâche »), raccourci affiché par `Context::format_shortcut` (relecture finale J4, F5 ; test `ui_edit_menu_structure_entries`).
- **Titre de la fenêtre.** `App::window_title()` (= `app::window_title_for`) : « *nom — planrs » si le document est modifié (`Session::is_dirty`), envoyé par `ViewportCommand::Title` au changement seulement. eframe web ignore cette commande : `apps/planrs-web` pose `document.title` depuis son observateur du document (`TabObserver`). La barre d'état affiche aussi « *nom » (`app::document_label`), seul indicateur dans la page (relecture finale J4, F4 ; test `ui_status_bar_shows_dirty_star`).
- **Langue de la session.** `document::load` ouvre la session en français ; l'interface ne s'en sert pas (messages d'erreur dans sa propre langue). Un lot de texte saisi (L12) doit porter `lang` (« 3d » est refusé par une session française sans `"lang":"en"`).
- **Canal de contrôle (desktop).** `App::set_observer(Box<dyn DocumentObserver>)` : l'observateur est appelé après chaque ouverture, fermeture, commit, annulation ou rétablissement. `apps/planrs` (`ControlRendezvous`) y tient le résumé servi par `query` (`view::summary`) et, quand le chemin du document change, lance l'écouteur `hello`/`query` (une fois, jeton `new_token`) puis publie le rendez-vous (`canonical_project`) ; l'ancien est retiré. Échecs signalés sur la sortie d'erreur, sans effet sur l'interface. Voir `docs/features/control.md`.

### 1.13 Édition des cellules et ligne vide de fin (J4, lot L12)

- **Colonnes éditables.** Nom, Durée, Début, Fin, Prédécesseurs (`edit::editable`) ; ID, marge et « Critique » sont calculées.
- **Cellule courante.** Curseur `ViewTransient::cursor: CellCursor<TaskUid, Column>` (J7 lot L1, remplace `TableEdit.column` et `TableEdit.blank`) : sa ligne est la tâche sélectionnée ou, sans sélection, la ligne vide de fin (`App::sync_selection` la pose) ; sa colonne est posée par un clic sur la cellule, Tab et les flèches. Dessinée : cadre de 2 px `Palette::cursor` (contraste ≥ 3:1 sur le fond, le fond alterné et la sélection, `palette_cursor_contrast`), sauf pendant une saisie ; nœud d'accessibilité de la cellule (`nav-cursor-label` : « Ligne 3, Durée, 5 jours » ; `nav-cursor-blank-label` sur la ligne vide). Saisie ouverte : `ViewTransient::edit` (`edit::TableEdit`), jamais sérialisé, remis à zéro à l'ouverture et à la fermeture.
- **Ouverture.** F2 ou double-clic : saisie avec le texte affiché, curseur en fin ; frappe d'un caractère (hors champ de texte ou autre widget focalisé que la table, menu ouvert, Ctrl/Cmd) : le caractère remplace la valeur. La zone de saisie (`TextEdit`, libellé `cell-edit-label`) est dessinée **dans** la cellule (`grid::show_editor`, apparence `grid::EditorLook` de la cellule, H-UI-85 ; table et feuille des ressources) et prend le focus clavier à l'image de son ouverture, état de saisie d'egui remis à neuf (identifiant partagé : ni défilement ni historique d'annulation d'une saisie précédente) ; les raccourcis de `KEYMAP` sont inactifs tant qu'une saisie est ouverte, même si sa zone n'a pas encore le focus. Ligne courante hors de l'écran (défilée à la molette) : elle est amenée à l'écran avec une ligne de marge (`TableEdit::reveal`, lu par la vue principale) et la zone est dessinée à l'image suivante ; la frappe reçue tant que la zone n'a pas le focus va au tampon (Retour arrière y efface un caractère). Relecture finale J7, F2 : la saisie ouverte hors de l'écran ne recevait que le premier caractère, et Retour arrière supprimait la tâche (test `ui_edit_offscreen_row_is_revealed_and_keeps_typing`).
- **Correctif du 2026-10-27 (H-UI-85, H-UI-86).** Cause : le double-clic qui ouvre la saisie pousse aussi `Action::FocusPane(Pane::Table)` ; appliquée par le réducteur **après** le dessin, elle redemandait le focus pour la table (`App::focus_pane`), qui le reprenait à la zone de saisie dans la même image. La zone restait donc affichée sans focus : pas de curseur de texte, pas de perte de focus détectable, et le clic suivant sur une autre ligne déplaçait la sélection (`Action::Select`, poussée sans condition par le clic) en laissant la zone ouverte sur l'ancienne cellule (capture du propriétaire). Correctifs : `focus_pane` ne donne plus le focus à la table tant qu'une saisie est ouverte ; un clic sur une cellule pendant une saisie ne sélectionne rien lui-même : il est rendu à `edit_cells`, qui valide d'abord puis active la cellule cliquée, ou garde la zone (et la sélection) si la saisie est refusée ; `App::sync_selection` ramène la sélection et la colonne du curseur sur la cellule en saisie si un autre chemin (Gantt, chronologie, agent) les a changées. Apparence : l'ancienne zone était un `TextEdit` d'egui avec son cadre arrondi blanc, la police par défaut d'egui (Ubuntu Light, plus fine et plus petite qu'Inter) et une marge propre, alignée à gauche.
- **Fin de saisie.** Entrée (ou flèche bas) valide et descend d'une ligne (de la dernière tâche vers la ligne vide ; sur la ligne vide, la ligne vide reste courante pour saisir des tâches à la suite), flèche haut ou Maj+Entrée valident et montent, Tab / Maj+Tab valident et passent à la colonne **visible** suivante / précédente, colonnes calculées comprises (H-UI-14, J7 lot L1 ; J4 : colonne éditable), Échap abandonne (la cellule éditée reste active, la table reprend le focus), un défilement vertical ou la perte du focus (clic dans le Gantt, le ruban, un menu) valident sur place, un clic sur une autre cellule valide puis l'active (H-UI-86). Le déplacement est une `Action::Nav` appliquée après le lot (Entrée sur la ligne vide : la tâche créée la précède, la ligne vide reste courante). Le lot part en `Action::ExecOn { opening, batch }` (numéro d'ouverture du document visé, lot abandonné si un autre document l'a remplacé) et le réducteur applique les lots d'édition de l'image **avant** les autres actions (partition stable) : une saisie validée par le clic sur un bouton de la barre d'outils, d'un menu ou du bandeau (dessinés avant la table) modifie d'abord le document, et « Ouvrir l'exemple », « Nouveau » ou « Fermer » demandent alors confirmation (relecture finale J4, F2 ; tests `ui_edit_focus_loss_commits_before_document_replaced`, `exec_on_other_opening_is_dropped`). Valider sans avoir rien changé depuis F2 ou le double-clic n'envoie rien (ni historique, ni contrainte posée par R-158 sur une date relue).
- **Lecture → lot (`edit::commit_edit`, pure).** Durée → `task.update duration {text}` (lue d'abord par `parse_duration` pour l'erreur sous la cellule) ; Début/Fin → `parse_date` (rôle Start/Finish) → `task.update start|finish`, R-158 appliquée par le registre ; Prédécesseurs → `parse_predecessors`, ID → UID côté interface (R-150 ; ID absent : `edit-error-unknown-id`), puis `link.remove` des anciens absents, `link.update` (type ou décalage changé), `link.add` (un lien pendant n'est pas touché) ; Nom → `task.update name`. Ligne vide : `task.add at End` portant la valeur saisie (nom vide pour une autre colonne que Nom ; prédécesseurs : `task.add as "$new"` puis `link.add` vers l'étiquette, un seul lot), rien si la saisie est vide. Le lot porte `lang` = langue de l'interface (la session est ouverte en français).
- **Refus.** Texte illisible : la saisie reste ouverte (avec le focus) et la sélection ne bouge pas, ni par les flèches ni par un clic (H-UI-86), message traduit sous la cellule (clé `error-text-<code>`, détail `CommandError::message`), effacé à la frappe suivante. Refus du registre (cycle, doublon, R-160) : bandeau « Modification refusée », la saisie est déjà fermée.
- **Texte initial et relecture (`ui_parse_display_roundtrip`).** Le texte initial est l'affichage s'il se relit à la même valeur, sinon l'écriture du moteur : « 5 jours écoulés » n'est pas une unité de R-140 (→ « 5ej ») ; une date de 2084 à 2149 affichée avec une année sur deux chiffres se relirait en 1984-2049 (→ « JJ/MM/AAAA hh:mm ») ; prédécesseurs non relisibles → écriture R-142. L'heure n'étant pas affichée, une date validée prend l'heure par défaut du rôle (R-033). Propriété vérifiée sur 256 cas, en français et en anglais.
- **Ligne vide de fin.** Une ligne de plus que de tâches dans la zone de défilement (table seulement, sans barre ni texte, libellé `blank-row-label`), visible au bas de la table ; elle ajoute une ligne de contenu, d'où les captures régénérées (curseur de la barre verticale, capture défilée).

### 1.15 Structure : insertion, suppression, hiérarchie, liens (J4, lot L14)

- **Sélection.** `App::selection` reste la tâche active ; `App::selected()` (`Selection`) porte l'ensemble, l'ancre et l'ordre des clics. Clic simple : une tâche ; Ctrl/Cmd+clic : ajoute ou retire ; Maj+clic : plage de lignes depuis l'ancre (remplace la sélection). La table et le Gantt ne poussent que `Action::Select` ; `main_view` le réécrit en `Action::SelectWith { uid, mode }` d'après les modificateurs de l'image. `App` resynchronise l'ensemble sur la tâche active quand elles divergent (clic simple, tâche supprimée, nouveau document, affectation directe de `App::selection`). Table et Gantt surlignent toutes les tâches sélectionnées (`FrameCtx::selected`).
- **Commandes** (`Action::Structure(StructureOp)`, contexte `Document`, jamais pendant une saisie) : Inser, ou Ctrl/Cmd+I (clavier Mac sans Inser, relecture finale J7, F6 ; affiché dans les menus sur macOS) → `task.add` (nom vide) `at: Before(première tâche sélectionnée dans l'ordre des ID)`, `End` sans sélection, la tâche créée devient la sélection ; Suppr (ou Ctrl/Cmd+Retour arrière, « Cmd+delete » d'un clavier Mac, affiché dans les menus sur macOS) → `task.delete` de chaque tâche sélectionnée sans ancêtre sélectionné, `cascade:true` pour une récapitulative ; Alt+Maj+→ / ← → `task.indent` / `task.outdent` dans l'ordre des ID, tâches dont un ancêtre est sélectionné exclues (le bloc ne bouge que d'un niveau) ; Ctrl+F2 → `link.add` FS en chaîne dans l'ordre des clics (ordre des ID pour une plage) ; Ctrl+Maj+F2 → `link.remove` de chaque lien dont les deux tâches sont sélectionnées. **Un seul lot** par commande (une entrée d'historique) : un doublon, un cycle ou une hiérarchie refusée font refuser tout le lot (R-153, R-156, R-160), refus traduit dans le bandeau. Rien à faire (sélection vide, un seul maillon, aucun lien) : aucun lot.
- **Confirmation.** Un lot de suppression contenant une récapitulative n'est pas appliqué : `App::pending_delete()` le garde avec le nombre de tâches supprimées (sous-tâches comprises) et la clé de cache du document ; une fenêtre modale (`confirm-delete-*`) demande « Supprimer » ou « Annuler » (Échap ou clic hors de la fenêtre = Annuler) → `Action::ConfirmDelete(bool)`. Une demande devenue caduque (document modifié, annulé ou changé entre-temps) est abandonnée sans effet. Les commandes de structure sont ignorées tant qu'une confirmation est ouverte.
- **Menu contextuel.** Clic droit sur une ligne de la table ou du Gantt : la ligne est sélectionnée si elle ne l'est pas (sinon la sélection multiple est gardée), puis un menu au pointeur propose les six commandes avec leur raccourci (`keymap::shortcut_for`) ; entrées autres qu'« Insérer une tâche » grisées sans sélection.
- **Hiérarchie lue côté interface** (ordre et niveaux seulement, aucun calcul de planning) : récapitulative = la tâche suivante est plus profonde (R-052) ; bloc = tâches suivantes plus profondes, lignes vides comprises (même parcours que `task.delete`).
- **Retour arrière seul** (touche « delete » d'un Mac) ouvre la saisie **vide** de la cellule courante, comme une frappe (à valider par Entrée, Échap abandonne) : il ne supprime plus la tâche (relecture finale J7, F6, qui revient sur la relecture finale J4, F5 : vouloir effacer une cellule supprimait la tâche entière, et la touche restait active le focus sur un bouton du bandeau ou dans le Gantt ; test `ui_backspace_clears_cell_not_task`).
- **Hypothèses (H-UI, non numérotées).** Insertion d'une seule tâche quelle que soit la taille de la sélection (MS Project en insère autant que de lignes sélectionnées) ; nom vide ; Ctrl+Maj+F2 sur une seule tâche ne retire rien (MS Project retire alors tous ses liens) ; Maj+Inser et Maj+Suppr déclenchent aussi Inser et Suppr (egui ignore Maj en trop).

- **Contenu.** En-tête : la tâche (une seule) ou le nombre de tâches sélectionnées (lignes vides exclues). Filtre sans casse sur le nom. Une ligne par ressource du projet (ressource cachée d'UID 0 exclue) : Affectée (« oui » si affectée à toutes les tâches de la sélection, « k sur n » sinon), nom (clic : choix ; Ctrl ou Cmd + clic : plusieurs), Unités (pourcentage pour une ressource de travail, quantité tirée du travail pour une ressource matérielle comme `assignment.list`, rien pour une ressource coût). Les unités affichées sont relues sur le modèle (communes à la sélection, vides si elles diffèrent).
- **Boutons, un lot chacun** (une entrée d'annulation), appliqué au clic, fenêtre gardée ouverte : « Affecter » (`assignment.add` pour chaque tâche × ressource choisie et visible non encore affectée), « Retirer » (`assignment.remove` des affectations existantes), « Modifier les unités » (`assignment.update` sur les tâches où la ressource est affectée, si les unités saisies ont changé). Unités vides : le lot ne les donne pas, le registre prend sa valeur par défaut (R-196 : capacité, au plus 100 % ; capacité 0 : ce que rend la règle) et la fenêtre l'affiche telle quelle. Texte des unités lu par le registre (« 50 » = 50 %) ; refus affiché dans la fenêtre, jamais dans le bandeau.
- **Relecture.** À chaque image où la clé du document ou la sélection a changé (édition, annulation, agent, clic dans la table) ; filtre, choix encore valides et saisies non appliquées gardés.
- **Hypothèses (non numérotées).** Choix par clic sur le nom ; les boutons ne visent que les ressources choisies **visibles** par le filtre ; « Affecter » laisse telle quelle une affectation déjà présente ; ni « Remplacer » ni « Graphes » (S70) en J7.

### 1.21 Desktop : capture relayée, fichiers récents, argument (J7, lot L14)

- **Capture (`app.screenshot`, C-CTL-08).** Permise seulement par le desktop (`App::enable_screenshots`, après `control_inbox`) ; ailleurs (kittest, web) `control.screenshot_unavailable` aussitôt. ### 1.22 Reprise après plantage (J7, lot L15)

- **Journal par document** (`planrs_automation::recovery`, natif seulement ; ADR-0005 « write-ahead », ADR-0015). Dossier `recovery_dir()` = `PLANRS_RECOVERY_DIR` (absolu) sinon `recovery` à côté du dossier du canal (`state_dir()/../recovery`), un sous-dossier `<pid>-<n>` (0700 sur Unix) par document ouvert : `base.json` (projet en JSON v1 du cœur, pas MSPDI : l'aller-retour MSPDI n'est pas l'identité ; plus nom, chemin, langue, « maintenant », compteurs d'UID, drapeau « enregistré », époque, et l'empreinte du fichier du document à la base, `file: { len, modified_ns }`, absente sans chemin), `ops.jsonl` (une ligne `{"epoch", "entry"}` par lot, annulation ou rétablissement, écrite puis `sync_data`), `lock` (verrou exclusif `File::try_lock` tenu par l'application vivante).
- **Suivi.** `App` appelle `RecoveryLog::record` à chaque notification du document (ouverture, lot, annulation, rétablissement, enregistrement, relais accepté, fermeture). Le `Recorder` déduit l'entrée de la position de l'historique (`Session::history_position`, `history_last_id`, `last_applied`) : nouveau lot ⇒ `Apply` (lot tel qu'appliqué, origine `User` ou `Agent`), retour à la position précédente ⇒ `Undo`, lot rétabli ⇒ `Redo`. **Point de reprise** (base réécrite par fichier temporaire et renommage, époque suivante, journal vidé) : à chaque état enregistré, tous les 500 changements ou 8 Mio, et quand un changement ne s'explique pas par une entrée que le rejeu saurait refaire (annuler au-delà de la base, plusieurs lots entre deux notifications). Les lignes d'une autre époque sont ignorées au rejeu : un plantage entre le renommage et la troncature ne rejoue rien deux fois.
- **Fermeture propre** (document fermé ou remplacé après confirmation, Quitter confirmé, fenêtre fermée sans rien à perdre) : journal supprimé. Plantage, « Quitter » du Dock ou fermeture de session sur macOS (§ 5) : le journal reste, verrou relâché ⇒ **orphelin**.
- **Démarrage** (`apps/planrs`) : orphelins sans modification (aucune entrée, base enregistrée) et bases illisibles (absentes, JSON invalide) supprimés ; journal d'une **autre version** de format ou base de plus de 512 Mio (`Orphan::kept`) **jamais supprimé d'office** : proposé sans Restaurer, avec un message, Ignorer le supprime (relecture finale J7, relais F5 : un retour à une version antérieure supprimait sans un mot le journal d'une version plus récente) ; les autres proposés un à un par le bandeau « Récupérer « plan.xml » (N modifications) ? » : **Restaurer** (rejeu ; document installé **marqué modifié**, historique des lots depuis la base annulable ; confirmation d'abord si le document courant est modifié ; orphelin supprimé), **Ignorer** (supprimé), **Plus tard** (bandeau retiré, journal gardé pour le prochain démarrage). Après un point de reprise, le bandeau dit que l'historique antérieur n'est plus annulable. **Fichier changé depuis la base** (empreinte différente : réécrit par une autre instance après « Plus tard », par `planrs mcp --headless`…) : le bandeau le dit et Restaurer installe le document **sans chemin**, nommé « plan (récupéré).xml » : Enregistrer demande un nom au lieu d'écraser la version plus récente (relecture finale J7, F3).
- **Rejeu** (`replay`, P48) : session sur la base (compteurs d'UID relevés : un UID alloué puis annulé n'est pas rendu deux fois), puis chaque entrée de l'époque ; une ligne illisible (écriture interrompue) ou une entrée refusée arrête le rejeu juste avant elle : ce qui précède est restauré, un message dit combien de modifications ont été rejouées et pourquoi la suivante est refusée. Base illisible : message, l'orphelin reste proposé (Ignorer le supprime).
- **Disque plein ou dossier inaccessible** : le journal est coupé (plus rien n'y est écrit, le préfixe reste récupérable), un avertissement s'affiche une fois, **l'édition n'est jamais bloquée** ; quand le document revient à son état enregistré, le journal partiel est supprimé et un nouveau est tenté.
- **Coût.** Une ligne et un `sync_data` par changement ; la base entière (JSON du projet) à l'ouverture et à chaque point de reprise (enregistrement compris). Non mesuré sur un réseau de 5 000 tâches (le test de fluidité ne branche pas de journal).
- **Web et kittest** : aucun journal (`App::set_recovery` jamais appelé).
- **Tests.** `planrs-automation/tests/recovery_properties.rs` : P48 (`p48_replay_restores_session`, 512 cas : projet, planning, état modifié, compteurs d'UID, historique entrée par entrée sans point de reprise, annuler/rétablir ensuite), `recovery_orphan_detected_after_lock_released`, `recovery_replay_stops_on_bad_entry`, `recovery_checkpoint_truncates`, `recovery_clean_orphan_not_worth_restoring`, `recovery_entry_roundtrip`, `recovery_replay_keeps_agent_source`, `recovery_file_changed_since_base_detected`, `recovery_foreign_or_large_base_kept` ; `tests/ui/recovery.rs` : `recovery_banner_restore_marks_dirty`, `recovery_restore_changed_file_drops_path`, `recovery_restore_confirms_dirty_document`, `recovery_discard_and_later`, `recovery_disk_full_never_blocks` (écrivain simulé) ; `apps/planrs` : `desktop_start_recovery_offers_and_cleans`, `desktop_start_recovery_keeps_foreign_journal`.

### 1.23 Lignes affichées (`RowView`, J8 lot L5, ADR-0016 D1)

- **Deux espaces d'indices.** Le `RowModel` reste dans l'ordre des ID (ligne du modèle = position dans le projet) ; la table, le Gantt, la navigation, la sélection en plage, les gestes et `app.ui_state.visible_rows` travaillent en **lignes affichées**. `row_view::DisplayRow(u32)` et `ModelRow(u32)` sont deux types distincts ; `RowView` garde `order` (affichée → modèle), `display_of` (modèle → affichée, `HIDDEN` = masquée) et les liens visibles (`DisplayLink { from, to, model_link }`, triés par plus petite ligne affichée puis indice du lien ; `links_touching(range)` comme `RowModel`). `VisibleRows` (modèle + vue, `FrameCtx::visible`, `App::visible_rows`) est le seul chemin de lecture d'une ligne affichée : `row(d)`, `text(d, colonne)`, `uid(d)`, `display_of(uid)`, `model_index_or_blank(d)` (ligne vide de fin = `RowModel::len()` pour la saisie).
- **Construction** (`RowView::build(model, FilterCtx, TaskViewState, repliées)`) : (1) filtre partagé de `planrs_automation::filter` (R-251, `FilterHits`, récapitulatives liées des préréglages) ; (2) repli : niveau affiché (`outline_level`, lignes de niveau supérieur masquées) et récapitulatives repliées (`ViewTransient::collapsed`, `BTreeSet<TaskUid>` ; le bloc qui suit une récapitulative repliée, jusqu'à la prochaine ligne de niveau inférieur ou égal, est masqué ; une feuille « repliée » ne masque rien) ; (3) tri (`SortSpec`) : « conserver la structure » trie les frères sous leur plus proche ancêtre affiché puis parcourt l'arbre (pile explicite), sinon tri global ; valeur absente (ligne vide, tâche non planifiée) toujours en fin de liste, ordre des ID à égalité ; Nom comparé replié (`fold_text`) puis exact ; Début, Fin, % du `RowModel` ; Durée et Marge totale du planning du moteur (règle 3) ; ID croissant = ordre du modèle ; (4) liens renumérotés. Cœur pur testable sans document : `RowView::compose(ViewInput)`.
- **Cache.** Reconstruite seulement quand change la clé (numéro d'ouverture et génération du document, langue, nombre de lignes, filtre, tri, niveau, version du repli) : à l'ouverture, après chaque édition (avec le `RowModel`), au changement de langue, et quand l'état de vue change (`App::set_task_view`, `set_collapsed`, `toggle_collapsed` ; commandes d'interface du lot L9, § 1.24 ; version de réapplication du filtre comprise). Sans filtre, tri ni repli : identité, liens du modèle compris, interface identique à J7.
- **Sélection.** Une tâche sélectionnée devenue masquée est retirée ; la tâche active masquée est remplacée par la prochaine tâche affichée dans l'ordre des ID (la précédente en fin de liste, aucune si rien n'est affiché : le curseur va à la ligne vide) ; une saisie ouverte sur une ligne masquée est abandonnée. Maj+clic prend les lignes **affichées** entre l'ancre et la tâche cliquée.
- **Aucune écriture (P50).** Filtre, tri et repli ne touchent ni la session ni l'historique ; les octets enregistrés sont inchangés.
- **Tests.** `row_view.rs` (unitaires) : P51 (`p51_row_view_is_a_partial_permutation`, proptest 4 096 cas), P53 (`p53_fold_unfold_is_idempotent`), exemples sur le projet « P » ; `tests/ui/row_view.rs` : `row_view_identity_is_j7`, `click_under_filter_and_sort_hits_right_task`, `drag_under_sort_uses_model_row`, `links_renumbered_culling`, `selection_dropped_when_hidden`, `nav_down_skips_hidden_rows`, `p50_view_operations_write_nothing`, `p53_app_fold_unfold_restores_view` ; `tests/perf.rs` : `filter_sort_5000`, `outline_5000` (`RowView::build` médiane < 8 ms, images médiane < 16 ms, p95 < 32 ms).

## 2. Rendu

- **Virtualisation.** Une seule `ScrollArea::vertical().show_viewport` englobe la table et le Gantt : les deux corps reçoivent la même plage `geom::visible_rows(viewport.top, viewport.bottom, ROW_H, len, OVERSCAN)` dans la même image (pas d'image de retard). Seules ces lignes (fenêtre + 2 de part et d'autre) sont parcourues ; aucun travail proportionnel au nombre de tâches pendant une image (textes pré-formatés, liens par `links_touching`, barres hors de la découpe horizontale non dessinées). Hauteur de ligne fixe 22 points, en-tête commun de 44 points à deux niveaux.
- **Barre verticale.** `ScrollStyle::solid()`, toujours visible (`ScrollBarVisibility::AlwaysVisible`) ; elle occupe `Metrics::vbar_w` à droite du corps, que `main_layout` retire au Gantt ; les coins au-dessus et au-dessous prennent le fond de l'en-tête.
- **Table.** Dessin direct au `Painter` : fond, zébrure, sélection, trait de ligne, texte de chaque cellule visible par une galley du cache d'egui (`LayoutJob` tronqué par « … », couleur `Color32::PLACEHOLDER` fixée au dessin), nom indenté par niveau (retrait plafonné), récapitulative en texte appuyé et faux gras. Texte en couleur normale : comme MS Project, la table n'est pas colorée par la criticité ; **seule la colonne « Critique » d'une tâche critique est en rouge** ; lignes vides et tâches exclues en texte atténué. Chaque ligne est une zone cliquable (`Action::Select`) qui déclare un `widget_info` `Role::Row` avec le libellé traduit `row-label` (accessibilité, `get_by_label` de kittest). `egui_table` n'est pas utilisé (egui 0.36, incompatible).
- **Gantt, ordre des couches** (`gantt::paint_body`) : fond → bandes du style → jours chômés → grille verticale aux frontières des deux niveaux → traits de lignes → bande de sélection → ligne de la date d'état (`effective_status_date`, tirets) et aujourd'hui → liens → lignes de base (suivi) → barres → motifs → bandes d'avancement (suivi) → textes autour des barres (J8, § 1.26). Barres : feuille (rectangle arrondi, contour), récapitulative (barre à crochets, rouge sombre si critique), jalon (losange), tâche exclue (contour gris), critique en rouge.
- **Jours chômés (J7 lot L7, N3).** Aux zooms Jour et Semaine, les jours sans plage ouvrée du calendrier du projet (`CompiledCalendar::day_ranges` vide : week-ends, fériés, exceptions chômées) sont grisés (`Palette::non_working`) sur toute la hauteur du corps, jours visibles consécutifs fusionnés (au plus un rectangle par jour visible). Les jours visibles sont ceux de `tier_spans` (même culling que la grille). Calendriers compilés par `OpenDocument::calendars()` : `document::CalendarCache`, compilé à la première demande de chaque génération de la session (`CalendarSet::compile_with`, budget `Limits::compiled_segments` du moteur), partagé par `Arc` ; rien n'est compilé aux zooms Mois et Trimestre. Calendrier du projet en échec ou hors budget : aucun grisé, une ligne de journal par génération ; le moteur, de même budget, a déjà émis son diagnostic `calendar.too_many_segments` (panneau des diagnostics).
- **Gantt de suivi (J7 lot L7, H-UI-22).** Menu Affichage → « Diagramme de Gantt » / « Gantt de suivi » (`Action::SetGanttStyle`, `UiState::gantt_style`, persistant). En suivi, une tâche dont la ligne de base 0 est enregistrée (`Row::baseline`, début et fin) a sa barre courante remontée au-dessus du tiers inférieur (`gantt::tracking_layout` : de 3 points sous le haut à 1 point au-dessus du tiers inférieur ; liens raccordés à ce centre) et sa barre de base pleine (`Palette::baseline`) dans le tiers inférieur (losange si début et fin de base coïncident ; ni pour une ligne vide ni pour une tâche exclue) ; sans ligne de base, barre courante seule, centrée comme en style standard. Bande d'avancement (`Palette::progress`) dans la moitié centrale de la barre d'une feuille commencée, sur [début, `Stop`] borné à la barre (`gantt::progress_span`, `Row::stop` du moteur, R-204) ; rien pour une récapitulative ni un jalon (hypothèse). Date d'état : la ligne déjà tracée dans les deux styles.
- **Infobulle d'une barre (J7 lot L7, H-UI-26).** Survol d'une barre (losange d'un jalon, 2 points de marge), après le délai d'egui (`Response::on_hover_ui`) : résumé du début de la tâche par la lecture typée `Query::Explain { task, side: Start, depth: 1 }` (même fonction qu'`analysis.explain_date`), texte du gabarit du moteur (`summary_fr` / `summary_en`, R-233) dans la langue de l'interface ; refus du moteur traduit (`error-<code>`). La zone de survol (`Sense::hover`, posée seulement sur la barre survolée) ne prend ni le clic ni le glisser du fond. Cache d'une entrée `(ouverture, génération, UID, côté)` dans la mémoire temporaire d'egui (`ExplainTipCache`) : la lecture n'est refaite qu'au changement de tâche ou de génération.
- **Liens.** `link_path(kind, p, s, metrics)` (pure, testée) : polyligne orthogonale d'au plus 6 points et pointe de flèche, cas direct et cas replié pour FS et SF, SS et FF par le côté correspondant ; un jalon se raccorde aux pointes de son losange. Culling par intersection d'intervalles de lignes puis par la boîte englobante du tracé.
- **Séparateur et barre horizontale.** Séparateur glissable (`SetTableWidth`, bornes `TABLE_WIDTH_MIN..=TABLE_WIDTH_MAX` et 200 points minimum pour le Gantt) ; barre horizontale minimale du Gantt (curseur proportionnel, glisser, clic sur la piste = une page).
- **Bandeau de messages** (sous le ruban) : texte fort (`text_strong`) sur fond teinté (`message_error_bg` ou `message_warning_bg`), liseré gauche coloré selon la gravité, titre traduit `open-error-title` s'il y a une erreur, bouton `message-dismiss` (« Fermer le message » / « Dismiss ») qui vide la liste. `App` garde au plus `MAX_MESSAGES` (3) messages, les plus récents, sans doublon ; le bandeau borne aussi à l'affichage.
- **Barre d'état** : nom du document, nombre de tâches, plage du projet, compteurs d'erreurs et d'avertissements (lus dans `DiagnosticsView`, cliquables : ouvrent ou referment le panneau).
- **Panneau des diagnostics** (`Panel::bottom` redimensionnable), ouvert ou refermé par les compteurs de la barre d'état (que rien ne signale comme cliquables) ou par la case « Diagnostics » du menu Affichage, toujours active (un panneau resté ouvert après « Fermer » se referme) : une ligne par diagnostic, colorée par gravité, tronquée (texte entier au survol), virtualisée par `ScrollArea::show_rows` ; sans document : « Aucun document ouvert » ; sans diagnostic : les deux compteurs à zéro.
- **Relevé.** `App::last_frame: FrameStats` : `table_rows` (écrit par `table::paint_body` seulement), `gantt_rows` (écrit par `gantt::paint_body` seulement), `links_painted`, `shapes` (formes émises par la vue principale, comptées à la main par les vues). Les deux plages venant de deux chemins de dessin distincts, les tests d'alignement peuvent échouer.

- ~~fichiers récents~~ (fait en J7 lot L14, § 1.21) ; redimensionnement des colonnes ; défilement horizontal de la table ; filtres ; tri ;
- panneau de diagnostics détaillé (version minimale seulement : une ligne par diagnostic, en français) ;
- ~~**jours chômés** non grisés dans le Gantt~~ (fait en J7 lot L7, `docs/ui-needs.md` N3 clos) ;
- profil `wasm-release` (LTO) ; ressources, utilisation, calendriers, panneau IA, enregistrement.

Constatés à la relecture et non corrigés :
- **polices non latines** (conclusion J7 lot L14) : sur le **desktop**, eframe 0.37 est pris avec ses features par défaut, dont `system_fonts`, et `NativeOptions::system_font_fallback` reste vrai (`desktop_keeps_system_font_fallback`) : un caractère absent des polices d'egui est cherché par `egui_system_font_provider` dans les polices du système (fontconfig, CoreText, DirectWrite). Vérifié par `fonts_system_fallback_probe` : les noms chinois de A6 (清明节, 劳动节) sont trouvés quand une police CJK est installée (job CI `ui` : `fonts-noto-cjk`, `PLANRS_FONTS=required`) et une ligne de table en CJK s'affiche sous kittest sans glyphe manquant. Sans police CJK sur la machine, boîtes vides : rien n'est embarqué (Noto CJK > 15 Mo). Sur le **web** et sous kittest sans fournisseur : polices d'egui seules (police de repli web : J8)
- ~~**erreurs d'ouverture non traduites**~~ (clos en J8 lot L14, § 1.29 : détail d'une erreur MSPDI traduit par code dans la langue de l'ouverture) ; le détail d'une erreur d'E/S reste le message du système (`docs/ui-needs.md` N9) ;
- ~~**contraintes ignorées sans diagnostic**~~ (clos en J3 : le moteur honore les contraintes de date et émet des diagnostics ; la tâche 41 de l'exemple démarre le 26/04, `docs/ui-needs.md` N4) ;
- « → » des diagnostics du cœur remplacé par « -> » à l'affichage (glyphe absent des polices d'egui) ;
- ruban (ADR-0017 L5) : déplié avec la frise, environ 216 points au-dessus de la table ; sur un écran de portable, replier par Ctrl/Cmd+F1 (aucun repli automatique) ; Cmd+F1 peut être pris par macOS selon les réglages du clavier (double-clic sur un onglet et menu Affichage restent) ; libellés français des onglets et groupes non relus sur l'interface française de MS Project ; onglets et barre d'accès rapide homonymes de menus pour l'accessibilité (rôles différents) ;
- `ScrollArea` d'egui 0.37 estompe le contenu près du bas de la zone (fondu de défilement) : la dernière ligne visible de la table et du Gantt apparaît pâlie ;
- étiquettes de l'en-tête de l'échelle de temps tronquées au bord gauche (« octobre 2… ») au lieu d'être recalées comme dans MS Project ;
- navigateur sans événement `cancel` sur le sélecteur de fichier (Safari < 16.4) : l'annulation ne répond jamais ; relancer « Ouvrir » abandonne la demande précédente ;
- web : le sélecteur est créé dans un futur lancé en fin d'image, donc hors du gestionnaire du clic ; il repose sur l'activation transitoire du navigateur (environ 5 s dans Chromium), à vérifier sur Safari ;
- clé `open-in-progress` (`TextId::OpenInProgress`) encore définie mais plus affichée depuis la relance de « Ouvrir » ;
- ~~`App` ne s'ouvre que depuis des octets MSPDI~~ (clos en J7 lot L14 : `App::open_project`, `docs/ui-needs.md` N8) ;
- la mesure de fluidité ne couvre que le CPU (construction + tessellation), pas le GPU ni le navigateur (facteur 2 à 3 attendu en wasm, non mesuré) ;
- macOS : binaire non signé (premier lancement par clic droit → Ouvrir ou `xattr -d com.apple.quarantine`, voir le README de l'artefact) ;
- sélecteur de fichiers réel jamais exercé par un test automatique (les tests injectent `NoFileService`, la CI n'a pas d'écran) : vérification manuelle sur chaque plateforme ; Windows et Linux non vérifiés, sélecteur non rattaché à la fenêtre sur ces deux plateformes ;
- Linux : X11 exige `libxkbcommon-x11` (paquet `libxkbcommon-x11-0`) ; « Ouvrir » exige un portail XDG (`xdg-desktop-portal`) ;
- aucune règle d'affichage n'est vérifiée contre MS Project (hypothèses H-UI, § 1.11).
- **web, enregistrement** : le document est marqué enregistré dès que le navigateur a reçu le téléchargement ; si le navigateur est réglé pour demander où enregistrer et que l'utilisateur annule sa boîte, la page n'en sait rien (aucune API ne le signale). Garde `beforeunload` (`apps/planrs-web`, drapeau `UnsavedFlag` tenu par l'observateur du document) : fermer ou recharger l'onglet d'un document modifié ouvre la boîte de confirmation du navigateur, dont le texte n'est pas personnalisable. Non vérifié dans un navigateur réel par un test automatique (seul `web_unsaved_flag_follows_document` tourne en natif ; le code wasm est compilé par clippy en `wasm32-unknown-unknown`) (relecture finale J4, F3) ;
- **macOS, « Quitter » du Dock, fermeture de session, arrêt** : appellent toujours `-[NSApplication terminate:]`, et le délégué de winit 0.30 n'implémente pas `applicationShouldTerminate:` ; l'intercepter demanderait un délégué Objective-C (`unsafe`, interdit par la règle 10, et winit refuse un délégué qui n'est pas le sien). Les modifications non enregistrées sont alors perdues sans confirmation. Seuls Cmd+Q, le menu Quitter et le bouton de fermeture de la fenêtre sont protégés (relecture finale J4, F1). Depuis J7 (lot L15), ces modifications ne sont plus perdues : le journal de reprise reste sur le disque et le bandeau de reprise les propose au démarrage suivant (§ 1.22) ;
- **reprise après plantage** (J7, lot L15, § 1.22) : le journal ne couvre que le desktop (rien sur le web : un onglet fermé sans enregistrer perd ses modifications, garde `beforeunload` seulement) ; la base est le projet entier en JSON, réécrit à l'ouverture et à chaque enregistrement (coût non mesuré à 5 000 tâches) ; l'historique antérieur au dernier point de reprise n'est plus annulable après une restauration ; les valeurs relues du fichier (R-162) ne sont pas journalisées (jetées de toute façon au premier lot) ; un document restauré dont le fichier a changé entre-temps (empreinte taille et date de modification, pas le contenu) s'ouvre sans chemin ; une réécriture qui garde la même taille dans la même nanoseconde n'est pas vue ;
- **ligne vide de fin** : apportée par L12 ; le test `ui_new_project_empty_with_blank_row` vérifie le document vide et la vue principale, pas la ligne vide (lot L13).
- **presse-papiers** (J8, lot L10, § 1.25) : texte seul (egui 0.37 n'a pas de type MIME) ; collage cellule par cellule reporté (R-256 réduit) ; la priorité et le calendrier d'une tâche copiée ne sont pas recollés (L3) ; Coller du menu jamais exercé sur un vrai presse-papiers (kittest ignore `RequestPaste`, les tests injectent `Event::Paste`) ; sur le web, le menu ne colle que le tampon interne ; Couper, Coller et « Collage spécial… » restent actifs sous un filtre ou un tri (le grisage des opérations de structure, H-UI-32, est au lot L9) ; une sélection masquée par un filtre n'est pas copiée (elle est retirée de la sélection, L5) ;
- **import CSV** : sélecteur réel jamais exercé par un test (comme « Ouvrir ») ; un fichier de plus de 64 Mio est refusé avant lecture ; l'aperçu décode le fichier entier à chaque changement d'option (un fichier de 64 Mio peut figer l'image le temps du décodage) ; les remarques de l'import sont comptées au bandeau, pas listées dans le panneau des diagnostics (typé MSPDI).
- **web, lot L13** (§ 1.28) : garde des raccourcis, bloc de chargement et téléchargements typés **non essayés dans un navigateur** par le lot (ni trunk ni navigateur sur la machine de développement) : essai manuel sous `trunk serve` (Chrome, Firefox, Safari : Ctrl+F, F3, copier/coller, PDF téléchargé) à faire ; Safari peut garder Cmd+F, G ou F3 malgré `preventDefault` (point ouvert 8 du cahier J8) ; la taille du `.wasm` (C-REL-05) n'est mesurée que par la CI de release ; noms CJK en boîtes vides sur le web (O55, aucune police de repli embarquée) non revérifiés sous trunk ; un fichier déposé pendant qu'une fenêtre modale est ouverte est ouvert quand même (bandeau si le document est modifié).

L'exemple `snapshot` utilise le même harnais que les captures (1280×720, 1 px par point, OS fixé, « maintenant » fixe au 2027-01-15) et préfère un adaptateur wgpu logiciel ; à défaut, il prend le premier adaptateur disponible et le signale (pixels alors différents de la CI). Langue et thème : français clair, sauf `main-dark` (français sombre) et `main-en` (anglais clair) ; `main-day` est défilée deux jours avant la date d'état ; `welcome` ignore le fichier ; `tracking` : Gantt de suivi ; `resources` : feuille des ressources ; `usage` : utilisation des ressources. `--generate N` (1 à 20 000) ouvre sans MSPDI le réseau du test de fluidité (`planrs_tests::generate::ui_network_with_resources` : lots de 20 tâches, N arrondi au multiple de 20 supérieur, deux liens par tâche, une ressource pour 25 tâches, « maintenant » au 2026-01-05) ; `--row N` sélectionne la ligne de tâche N (depuis 0) et y défile la table et le Gantt (début de la barre) ; `--zoom` impose l'échelle après la vue ; `--size LxH` (côtés de 320 à 4 096) remplace 1280×720. Le test `snapshot_generate_and_views` inclut l'exemple et prépare chaque vue.
