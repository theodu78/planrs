# Cahier des charges J4 — planrs (session, registre, undo, dry_run, CLI, SVG, MCP, édition egui)

Référence : ADR-0012 (`docs/decisions.md`). Branche `j4`. Toute règle ci-dessous est au statut `hypothèse` sauf mention. Chaque lot : un agent, ≤ ~1 500 lignes (code + tests), un commit `type(scope): …` par sous-étape testée, checks `cargo fmt --check`, `cargo clippy --workspace --all-targets -D warnings`, `cargo test -p <crates du lot>`, `cargo xtask panics`, `cargo xtask layers`, `cargo deny check` (si dépendances). Mémoire : builds en `-j2`, via `memlimit`.

## 0. Arbitrages entre propositions (rappel, détail dans ADR-0012)

| Désaccord | Tranché | Pourquoi |
|---|---|---|
| Undo : `Txn` pré-images (noyau) / instantanés plafonnés (pragmatique) / copie + échange + delta (adversaire) | Copie + échange + delta par entité | Atomicité et dry_run sûrs par construction (brief § 6 : « sur une copie ») ; mémoire durable aussi basse que les pré-images ; ~400 lignes au lieu de 900 |
| Trois API de session | `Session::apply(&Batch, ApplyMode)` (noyau) ; `Workspace` = couche fine | Un seul jeu de types |
| Plage R-150+ attribuée trois fois | Numérotation unique ci-dessous, tenue par ce cahier | Sens contradictoires (suppression, désindentation) |
| Suppression d'une récapitulative | `cascade:true` obligatoire ; l'interface confirme puis envoie `cascade` | Appelant agent ; écart MS Project signalé |
| Désindentation | Bloc (tâche + descendants) −1 ; les frères suivants restent à leur niveau, donc deviennent enfants | Conséquence naturelle du modèle par niveaux (R-052), comportement MS Project |
| Début/Fin saisis → contrainte | Dans `task.update` du registre (pas dans l'interface) | Une seule sémantique pour MCP, CLI, interface |
| Format des durées | `{"minutes","unit","text"}` en sortie, sous-ensemble valide en entrée | Une sortie est réinjectable telle quelle |
| Deux journaux | Un JSONL d'enveloppes `{seq, request, result?}` | Sert au rejeu `build_30` et à la trace |
| Diff : N = 20 (noyau) / 10 (surfaces) | 10 par défaut | Concision pour le LLM ; `detail:true` pour plus |
| Canal : complet J4 / reporté J7 / protocole seul | Protocole + rendez-vous + écouteur `hello` + garde `file.open_in_app` | ADR-0002 sans double écrivain, sans doubler le panneau IA J7 |
| PNG, HTTP, RD1 | PNG → J7 ; HTTP dernier lot coupable ; RD1 après le critère | Hors critère de fin ; dépendances lourdes |
| Formateurs d'affichage | Restent dans l'interface en J4 ; `render` n'affiche que ID et noms | `render` ne peut pas dépendre d'`automation` ; évite de toucher aux 7 captures |
| Mesure du texte SVG (ab_glyph) | Troncature au nombre de caractères (H-R) | Aucune dépendance nouvelle, déterministe |
| Doublon C1 (marges/rollup) | Un seul lot cœur L15 | — |

- **Fichiers** : `session.rs`, `history.rs`, `delta.rs` (delta de diagnostics), `diff.rs` (diff de planning), `uid.rs`, `entity_delta.rs` (comparaison de projets), `crates/planrs-automation/tests/session_properties.rs`, `tests/rules/r151_*.rs`, `r160_*.rs`, `r162_*.rs`, `r163_*.rs`, `r164_*.rs`.

- **Pipeline `apply`** (ordre exact) :
  1. `batch.format_version != 1` → `batch.unsupported_version`. `ops.len() > max_ops_per_batch` → `limit.exceeded`. `ops` vide → `Ok` sans commit ni entrée d'historique (`committed:false`).
  2. `let mut work = self.project.clone();` `uids` cloné ; labels vides.
  3. Pour chaque op `i` : `exec(ctx{op_index:i})` ; une erreur interrompt → `Err(e.with_op_index(i))`, état intact.
  4. `let v = work.validate(); let s = planrs_core::schedule(&work);`
  5. Delta de diagnostics (R-160) entre `self.project.validate() ∪ self.schedule.diagnostics` (mis en cache à chaque commit) et `v ∪ s.diagnostics`. Nouvelles erreurs → `batch.would_create_errors` avec la liste, `op_index` = dernière op ayant touché le sujet (`touched`), sinon dernière op.
  6. `diff = diff_schedules(&self.project, &self.schedule, &work, &s, N)` (R-163).
  7. `DryRun` : renvoyer `ApplyOutcome { committed:false, … }` ; `self` intact (vérifié par test).
  8. `Commit` : `delta = diff_projects(&self.project, &work)` ; échange (`self.project = work`, `self.schedule = s`), `self.uids = uids` ; si `recorded.is_some()` → `None` + `SideEffect::RecordedDiscarded` (R-162) ; empiler `HistoryEntry { label, ops: batch.clone(), delta, bytes }` ; vider la pile redo ; appliquer le budget (R-164) ; `generation += 1`.
- **Règles** :
  - **R-151 — Allocation des UID.** `next = max(max_uid des tâches, dernier alloué) + 1`, calculé par `checked_add` ; débordement de `u32` → `limit.exceeded { what:"task_uid" }` ; jamais 0 ; l'undo ne recule pas `next`, le redo réapplique les post-images (mêmes UID). Après rechargement du fichier, un UID supprimé peut revenir (hors session). Exemple : tâches {1, 2, 7} → prochain 8 ; ajout (8), undo, ajout → 9 ; fichier avec UID 4 294 967 295 → `task.add` refusé `limit.exceeded`.
  - **R-160 — Refus sur nouvelle erreur.** Clé d'un diagnostic de gravité `Error` = `(code(), subject())`, sauf `link.cycle` dont la clé est l'ensemble trié de `tasks`. Une erreur d'après est « nouvelle » si sa clé n'est pas dans l'avant ; pour `link.cycle`, si son ensemble n'est inclus dans aucun ensemble de cycle d'avant. Avertissements et infos nouveaux → `warnings` (triés, dédoublonnés), jamais bloquants. Exemples : cycle {5,7,9} existant, lot qui retire le lien 9→5 laissant {7,9} → accepté ; projet sans cycle, lien 3→1 alors que 1→3 existe → refus `batch.would_create_errors [link.cycle {1,3}]`, `op_index` = index du `link.add` ; fichier importé avec `link.unknown_task` sur la tâche 12, renommage de la tâche 4 → accepté.
  - **R-162 — Valeurs relues jetées au premier commit.** Tant qu'aucun commit n'a eu lieu depuis l'ouverture, `save_bytes` passe par `choose_computed(project, schedule, recorded)` ; après le premier commit, `recorded = None` et l'écriture utilise les valeurs du moteur (ou `Omit` selon `choose_computed` si des manques R-122 subsistent). Un undo jusqu'à l'état d'ouverture ne restaure pas `recorded` (hypothèse : préférer les dates du moteur). Exemple : `house.xml` ouvert puis enregistré sans modification → octets de `Computed::Recorded` ; après un `task.update name` puis undo → écriture `Computed::Schedule`.
  - **R-163 — Diff de planning.** Jointure triée des `Schedule.tasks` avant/après par UID (ajoutées : `before = None` ; supprimées : `after = None`). « Changée » ⇔ début ou fin planifiés (`TaskSchedule.start/finish`) différents, ou apparue/disparue ; marge et criticité seules ne font pas une tâche changée mais alimentent `critical_entered/left` (toutes les tâches, triées par UID). `finish_delta_min` = minutes écoulées fin après − fin avant (0 si un côté absent). Tri : |Δ fin| décroissant, puis ID après croissant (absent en dernier), puis UID. `changed` limité à N (10 par défaut, `detail` → `diff_detail_max` 1 000), `changed_total` exact, `truncated` si coupé. Exemple (calendrier standard) : A (UID 1) 5 j depuis lun 02/11/2026 08:00, fin ven 06/11 17:00, passée à 7 j → fin mar 10/11 17:00, Δ = 4 jours écoulés = 5 760 min ; B (UID 2, 1 j, FS de A) fin lun 09/11 17:00 → mer 11/11 17:00, Δ = 2 880 min ; C (UID 3) indépendante, non changée. `changed = [A, B]`, `changed_total = 2`, `project_finish` (09/11 17:00 → 11/11 17:00).
  - **R-164 — Historique.** Une entrée par lot commité ; `undo` applique la pré-image, recalcule `schedule` (déterministe), `generation += 1` ; `redo` la post-image. Un nouveau commit vide la pile redo. Budget : tant que Σ `bytes` > `history_bytes` ou nombre > `history_entries`, retirer la plus ancienne et incrémenter `dropped` (exposé dans `history()`). Une entrée seule plus grosse que le budget est gardée (au moins une annulation possible). `undo` sur pile vide → `history.empty`. `is_dirty` ⇔ position courante ≠ `saved_at` (une position abandonnée par le budget ⇒ `saved_at = None` ⇒ sale). Exemple : budget 2 entrées, lots A, B, C → historique [B, C], `dropped = 1`, deux undo possibles, le troisième `history.empty`.
- **Propriété P30** (`session_properties.rs`, 512 cas en CI) : sur projets générés (`planrs_tests::generate`) et lots générés de commandes de test (mutations directes d'entités, réordonnancements, suppressions), `undo(apply(p)) == p` (égalité `Project` et `Schedule`), `redo(undo(apply(p))) == apply(p)`, dry_run ne change ni `project`, ni `schedule`, ni `history`, ni `generation`. Étendue en L4/L5 aux vraies commandes.
- **Tests exigés** : `r151_uid_monotone_after_undo`, `r151_uid_overflow_refused`, `r151_uid_never_zero`, `r160_existing_error_not_blocking`, `r160_new_cycle_refused_with_op_index`, `r160_cycle_shrink_accepted`, `r160_new_warning_returned`, `r162_unmodified_save_uses_recorded`, `r162_first_commit_discards_recorded`, `r163_diff_sorted_and_truncated`, `r163_critical_entered_left`, `r163_added_and_deleted_tasks`, `r164_budget_drops_oldest`, `r164_redo_cleared_by_commit`, `r164_dirty_tracking`, `session_dry_run_untouched`, `session_atomic_on_error`, `session_empty_batch_noop`, `session_clone_cost_5000` (mesure informative : taille et temps du clone à 5 000 tâches, journalisée ; échec seulement dans le job `perf` si > 10 ms), P30.

## L4 — Commandes de tâches

- **Objectif** : `Exec` pour `task.add`, `task.update`, `task.delete`, `task.move`, `task.indent`, `task.outdent` ; table d'invalidation des `Extras` (partie tâches).
- **Fichiers** : `command/task.rs`, `command/outline.rs` (calculs de blocs), `command/extras_invalidation.rs`, `tests/rules/r152_*.rs` à `r155_*.rs`, `r157_*.rs`, `r158_*.rs`, `r161_*.rs`, extension de P30.
- **Règles** :
  - **R-152 — `task.add`.** `Task::new(uid, name, &options)` (durée `default_duration` estimée : « 1 jour? » = 480 min estimé) ; projet planifié à rebours → contrainte ALAP (hypothèse : MS Project crée des tâches « le plus tard possible » à rebours) ; `duration` fournie → non estimée sauf `estimated:true` ; durée 0 ⇒ jalon (R-157). Placement : `End` → dernière position, niveau 1 ; `After(t)` → après le **sous-arbre** de `t`, même niveau que `t` ; `Before(t)` → juste avant `t`, même niveau ; `FirstChildOf(p)` → juste après `p`, niveau p+1 ; `LastChildOf(p)` → après le sous-arbre de `p`, niveau p+1. Une feuille qui reçoit un enfant devient récapitulative ; si elle avait des liens, ils restent (R-056/R-057 s'appliquent). Nom vide accepté (MS Project l'accepte) ; nom > 512 caractères → `param.invalid` (borne `Task/Name`). `start`/`finish` → R-158. Exemple : projet [1 A (n1), 2 A1 (n2), 3 B (n1)] ; `add "X" at After(1)` → [A, A1, X(n1), B], X en ID 3, `IdsRenumbered{from:3,count:2}`.
  - **R-153 — Indentation, désindentation.** `task.indent t` : refusé (`task.outline_refused`) si `t` est la première tâche ou si niveau(t) > niveau(précédente) (on ne peut dépasser précédente + 1) ; sinon le bloc (t + descendants) prend +1. `task.outdent t` : refusé si niveau(t) = 1 ; sinon le bloc prend −1 ; les frères suivants de `t` (même ancien niveau, jusqu'à la fin du parent) restent à leur niveau et deviennent donc enfants de `t`. Niveau maximum 65 535 (`OutlineLevel`) → `limit.exceeded`. Un lien que la nouvelle hiérarchie rend « récapitulative ↔ descendante » est refusé par R-160 (`link.summary_descendant`, R-059). Exemple : [1 P(1), 2 a(2), 3 b(2), 4 c(2)], `outdent 3` → [P(1), a(2), b(1), c(2)] : c devient enfant de b.
  - **R-154 — `task.move`.** Déplace le sous-arbre entier de `t` (bloc contigu) au placement (même sens que R-152, cible résolue **avant** retrait) ; décalage de niveau appliqué à tout le bloc ; cible dans le bloc lui-même (`t` ou un descendant) → `task.move_into_subtree`. Implémentation par `Arena::splice`/`reorder` (L1). Exemple : [1 A(1), 2 A1(2), 3 B(1), 4 B1(2)], `move 3 to FirstChildOf(1)` → [A(1), B(2), B1(3), A1(2)].
  - **R-155 — `task.delete`.** Récapitulative sans `cascade:true` → `task.has_children { count }`. Supprime la tâche (et, en cascade, tout son sous-arbre) ; retire tous les liens dont elle est prédécesseur (index inverse construit une fois par lot sur le clone) — ceux dont elle est successeur partent avec elle ; retire ses affectations ; `SideEffect::TaskDeleted`, `LinkRemoved`, `AssignmentRemoved`, `IdsRenumbered`. Les UID ne sont pas réutilisés (R-151). Exemple : 5 tâches, 2→4 et 4→5, delete 4 → liens 2→4 et 4→5 retirés, tâche 5 devient ID 4.
  - **R-157 — Champs calculés d'une récapitulative.** Sur une récapitulative automatique : `duration`, `start`, `finish` → `task.computed_field` (champ nommé). Sur une feuille : `duration` 0 ⇒ `milestone = true` ; `milestone:true` sur une durée > 0 : drapeau posé, durée gardée (MS Project affiche un losange à la date de début ; hypothèse). Tâche manuelle (`mode = Manual`) : `start`/`finish` → `task.manual_unsupported` (V1 ne recalcule pas les manuelles, ADR-0005). Exemple : `update 1 duration 3j` où 1 a des enfants → `task.computed_field`, `field:"duration"`.
  - **R-158 — Début/Fin saisis.** Projet depuis le début : `start = d` → contrainte SNET date `d` ; `finish = d` → FNET `d` (S30, comme `CsvDates::Constrain`). À rebours : SNLT / FNLT (hypothèse). `Clear` → ASAP (ALAP à rebours). Une contrainte de date déjà présente est remplacée ; `SideEffect::ConstraintSet`. La date saisie passe par R-090 (normalisation) dans le moteur, pas ici. Exemple : `update 3 start 2026-11-04T08:00` → `Constraint::StartNoEarlierThan(2026-11-04T08:00)`, réponse : début planifié 04/11 08:00 si aucun lien ne pousse plus tard, sinon la date du moteur et un `constraint.*` éventuel en avertissement.
  - **R-161 — Invalidation des `Extras` (tâches).** Table `(champ modifié) → clés d'Extras jetées`, établie contre `planrs_mspdi::schema` et figée par un test : `duration`, `start`/`finish` (contrainte), `milestone`, `active`, liens modifiés, changement de hiérarchie → `TimephasedData`, `LevelingDelay`, `LevelingDelayFormat`, `PreLeveledStart`, `PreLeveledFinish`, `Resume`, `Stop` ; `name`, `notes` → aucune clé. Affectations de la tâche dont la durée change : `TimephasedData` et `Rates` de l'affectation jetés. Chaque entrée jetée → `SideEffect::ExtrasDropped { subject, keys }`. Exemple : tâche relue avec `<LevelingDelay>4800</LevelingDelay>` en Extras, `update duration` → clé jetée, effet listé, MSPDI réécrit sans `LevelingDelay`.
- **Tests exigés** : `r152_add_defaults_estimated_1d`, `r152_add_backward_alap`, `r152_placements_all_five`, `r152_name_too_long_refused`, `r153_indent_first_refused`, `r153_indent_jump_refused`, `r153_indent_block`, `r153_outdent_siblings_become_children`, `r153_outdent_level1_refused`, `r153_indent_creates_summary_descendant_link_refused`, `r154_move_subtree_with_levels`, `r154_move_into_own_subtree_refused`, `r155_delete_summary_requires_cascade`, `r155_delete_cascade_removes_links_assignments`, `r155_ids_renumbered`, `r157_summary_duration_refused`, `r157_zero_duration_milestone`, `r157_manual_dates_refused`, `r158_start_snet`, `r158_finish_fnet`, `r158_backward_snlt_fnlt`, `r158_clear_asap`, `r161_duration_drops_leveling_extras`, `r161_rename_keeps_extras`, P30 étendue aux commandes de tâches.
